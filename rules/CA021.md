# CA021: a rotor is configured but not counted by CA_ROTOR_COUNT

Level: warning

## What it checks

The input sets geometry parameters of a rotor whose index is `CA_ROTOR_COUNT`
or higher. A rotor counts as configured when its position (`CA_ROTORn_PX`,
`_PY`, `_PZ`), the x or y part of its thrust axis (`_AX`, `_AY`) or its tilt
servo (`_TILT`) is not zero. Zero is PX4's default for all of these.

## Why it matters

PX4 only reads the parameters of rotors 0 to `CA_ROTOR_COUNT` - 1. A rotor
above that is left out of the effectiveness matrix without a message, so the
vehicle is allocated as if it had fewer motors. The matrices of the remaining
rotors can still look reasonable: with PX4 v1.17.0
`examples/hexa_rotor_count_4.params` has no other finding. PX4 versions that
report dropped axes add CA002 for it, because the four remaining rotors cannot
control yaw independently of roll and pitch; that finding does not name the
cause.

If `CA_ROTOR_COUNT` is missing altogether its default of 0 applies and CA001
is reported as well.

## Example

`examples/hexa_rotor_count_4.params`: six rotors are described, but
`CA_ROTOR_COUNT` is 4. PX4 allocates to motor0 to motor3; the finding names
motor4 and motor5.

## What to do

Set `CA_ROTOR_COUNT` to the number of rotors. If the extra rotors are left
over from an earlier configuration, as can happen in a parameter export of a
vehicle that had more motors before, set their parameters back to the defaults
or skip the rule with `--ignore CA021`.

Rotors that only differ from the defaults in `CA_ROTORn_AZ`, `_CT` or `_KM`
are not found, because these parameters have non-zero defaults.
